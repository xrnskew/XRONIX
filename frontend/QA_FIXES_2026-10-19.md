# QA fixes — 19 October 2026

- Conversation state and pending replies are isolated per chat and login generation. New chat, switching while a request is pending, late failures, duplicate send and logout no longer reuse another chat's UI state.
- Plan cards select their plan_id. Plan and finance use the selected object. Missing/deleted deep links show an error rather than a stale plan.
- The working app uses /app#/plan?plan=… and /app#/finance?plan=…; direct links and reload restore the selected section and plan without GitHub Pages 404s. The presentation's internal router stays independent.
- Product-specific amount/term limits apply to the controls and calculations. The UI describes debt load rather than claiming bank eligibility. A mismatch with the actual funding gap is explicit.
- Refusal of credit has a separate no-loan funding screen. Submitted questionnaires retain their choices, including older histories.
- Launch-cost totals and unallocated amounts are visible next to steps; demo figures are consistent with their step costs.
- Real browser credentials are no longer stored in localStorage/sessionStorage. The matching backend supplies HttpOnly cookies; logout is server-side. Legacy storage is removed. Users sign in once after upgrading. The mock presentation remains backend-independent.
- Production HTML has a CSP limiting scripts/resources and a referrer policy. GitHub Pages cannot supply arbitrary HTTP response headers: frame-ancestors/X-Frame-Options, frontend HSTS and nosniff remain hosting work. Do not claim the entire original S01 finding closed.
- The 180-second AI timeout and the teammate's existing long-wait hints are preserved.

Validation: 17 Node regressions, 3 Python snapshot/parser tests, TypeScript check and Vite production build. Browser checks on a local real frontend + isolated mock-AI backend: login, cookie restoration, hash deep link/reload, no-credit funding, retained questionnaire choices and logout. Session regressions use deferred requests to verify out-of-order completion and session resets.

Deploy order: backend branch first, health/cookie smoke checks, then frontend branch (GitHub Pages workflow). Backend details live in backend/QA_FIXES_2026-10-19.md on the backend branch. Previously saved plans are repaired on read by the backend; historical geography assumptions are not silently rewritten.
