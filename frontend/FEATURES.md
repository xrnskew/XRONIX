# Контекст, генерация и безопасность аккаунта

Рабочий API-клиент отправляет сообщения через POST /chats/{id}/generations с уникальным
request_id, затем опрашивает GET /generations/{id}. При сетевой неопределённости повтор
использует тот же ключ; после подтверждённого сбоя создаётся новая попытка. Во время
ожидания можно обновить страницу: идентификатор выбранного чата хранится в sessionStorage
отдельно для каждого пользователя; статус и результат восстанавливаются из сервера.
Повторный вход и переключение чатов не смешивают поздние ответы. Анкета восстанавливает
ответы по question_id из сохранённой истории. Тексты и пароли в sessionStorage не сохраняются.

В профиле доступны смена пароля с проверкой текущего и выход со всех устройств.
Обе операции завершают текущий сеанс. На входе есть восстановление по почте через VE3.
Одноразовый секрет передаётся во фрагменте ссылки /app?recover=1#reset=… и удаляется из
адресной строки при открытии формы. После успешного сброса нужен обычный вход.
Подтверждение email при регистрации не добавлено.

Моковый режим не отправляет писем; в презентационном автопоказе управление безопасностью
отключено. Для настоящего восстановления нужны VITE_USE_MOCKS=false и рабочий backend.
Backend-контракт дополнен в ветке backend: contracts/api.md и contracts/ai.md.
