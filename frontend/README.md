# Frontend

React + Vite + TypeScript + Tailwind v4 + react-router + Recharts. Контракты: [`/contracts`](../contracts).

```
cd frontend
npm install
npm run dev      # http://localhost:5173
npm run build
npm test          # unit-тесты
npm run smoke    # дымовая проверка экранов на моках (нужны запущенный npm run dev -- --port 5199 и Playwright)
```

## Режимы
- `VITE_USE_MOCKS=true` (по умолчанию): мок-бэкенд в памяти (`src/api/mock.ts`) с теми же вызовами и формами ответов, что в `contracts/api.md`. Токен не сохраняется, при перезагрузке снова экран входа. В чат можно написать слово `!ошибка`, чтобы показать экран ошибки ИИ.
- `VITE_USE_MOCKS=false`: запросы идут на `/api/*`. Vite проксирует `/api` на `http://localhost:8000` (бэкенд Ильи). Другой адрес: `VITE_API_URL=https://...`. Токен хранится в `localStorage`.

## Структура
- `src/api`: клиент (`client.ts`: токен, таймауты, ошибки, 401), мок (`mock.ts`), единая точка `api` (`index.ts`).
- `src/phone`: рамка iPhone и кабинет. `CabinetContext.tsx` держит сессию, план, чат. Экраны: вход и регистрация, онбординг, чат со списком диалогов, план, финансы, профиль.
- `src/landing`: презентация слева (`Slides.tsx`), шапка и управление автопоказом (`Landing.tsx`), шейдерный фон.
- `src/phone/demo.ts` и `Director` в `phone/Cabinet.tsx`: сцены автопоказа.
- `src/data/alfaProducts.ts`: продукты Альфа-Банка, все цифры в одном файле. Перед защитой сверить с alfabank.ru/sme.
- `src/types/plan.ts`: типы повторяют `/contracts/schemas`.

## Ошибки в интерфейсе
`401 UNAUTHORIZED` возвращает на вход с пояснением. Сеть и таймаут (15 с, для ответа ИИ 35 с) показываются в чате с кнопкой «Повторить». Остальные коды показывают `message` из ответа бэкенда как есть.

## Автопоказ
Телефон справа показывает сцену, соответствующую слайду слева: вход, пустой чат, диалог с ИИ (печатается сам, шаги слева подсвечиваются по ходу), план (сам прокручивается к шагам и рискам), кредит (к продуктам банка), профиль, итоговый чат.

- Данные берутся из заготовок (`mocks/data.ts`), к бэкенду автопоказ **не обращается** и сессий не создаёт, в том числе с `VITE_USE_MOCKS=false`.
- Сцена переключается, когда прокрутка слайдов остановилась (220 мс), поэтому при быстром скролле ничего не мелькает.
- Как только человек коснулся телефона, автопоказ выключается, телефон остаётся у него. Вернуть можно переключателем в шапке (с настоящим бэкендом он выходит из аккаунта) или кнопкой «Попробовать самому» в начале.
- Если есть сохранённый вход (настоящая сессия), автопоказ не включается.
- На экранах уже, чем 1024 px, автопоказ отключён: телефон лежит над слайдами и не закреплён.
- Прокрутка внутри телефона не передаётся странице (`overscroll-contain`), а чат прокручивает только свой список. Не используйте `scrollIntoView` внутри телефона: он двигает и страницу.

## Анимации и 3D
- **Телефон в 3D** (`phone/Phone3D.tsx`, `phone/PhoneFrame.tsx`): у корпуса есть толщина (стопка слоёв за лицевой гранью), блик на стекле бегает при наклоне. Телефон поворачивается к курсору, на каждом слайде у него свой базовый ракурс (`angles` в `landing/Landing.tsx`), над самим телефоном наклон гасится. На узких экранах и при reduced-motion он плоский.
- **Анимации текста** (`landing/reveal.tsx`): `SplitText` (заголовок по словам), `Reveal` (проявление со сдвигом и снятием размытия), `FadeWords` (текст проявляется по словам). Слайд сообщает, виден ли он, и анимации проигрываются каждый раз, когда он снова входит в кадр. Числа на слайде «План» набегают, шкала вердикта растёт, схема архитектуры рисуется.
- **Вокруг телефона** (`landing/Satellites.tsx`): карточки-спутники для каждого слайда (сообщение, сумма, прибыль, график, платёж, кольцо нагрузки, теги), стоят колонкой слева от телефона и не заходят на экран, висят в 3D на разной глубине и плавают. Цифры берутся из того же плана, платёж пересчитан по аннуитету. Только в автопоказе и от 1280 px: когда человек берёт телефон, карточки гаснут и телефон возвращается в центр. За телефоном медленные орбиты со светящимися точками.
- **Фон** реагирует на прокрутку: граница красного в шейдере смещается вместе со страницей.
- **Мягкие края**: у слайдов нет цветных подложек с границами (радиальный градиент `.tint`), шапка растворяется вниз и вправо (`.header-fade`).
- Всё это отключается при `prefers-reduced-motion`: текст показывается сразу, телефон не наклоняется.
- **Не вкладывайте экран телефона в 3D-сцену.** Толщина корпуса лежит отдельным слоем позади, лицевая часть плоская (`PhoneFrame.tsx`). Если экран станет частью `preserve-3d`, Chrome перестаёт понимать, что под курсором: поля ввода не ловят мышь, курсор мигает. Пока курсор над телефоном, он замирает (`Phone3D.tsx`).
- **Производительность:** каждый кадр меняются только `transform` телефона и блика, никаких CSS-переменных на предках. `backdrop-filter` и `filter: blur` поверх анимированного фона не используем: они пересчитываются каждый кадр. Шейдер рисует в половинном разрешении и не чаще 30 кадров в секунду. Тяжёлый кабинет обёрнут в `useMemo` и не перерисовывается от прокрутки.
- Внутри телефона не используйте `transform`-зависимые измерения (`getBoundingClientRect`) для прокрутки: телефон масштабируется и наклоняется, смотрите `scrollPhone` в `phone/demo.ts` (считает по `offsetTop`).

## Листание слайдов
`useSlideScroll` в `landing/useSlides.ts`: на экранах от 1024 px один жест колесом или трекпадом листает ровно один слайд (плавно, 0,7 с). Пока идёт анимация и хвост инерции трекпада, новые шаги не делаются, поэтому длинный свайп не перелистывает несколько слайдов. Если слайд выше окна, сначала дочитывается он. Клавиши: стрелки, PageUp/PageDown, пробел, Home/End. Колесо над прокручиваемым экраном телефона прокручивает телефон. `scroll-snap` не используется: он тянул короткие прокрутки назад, и колесо казалось медленным.

## Большие мониторы
Вёрстка нарисована под 1440×900. На больших экранах (`lib/uiScale.ts`) всё увеличивается одним коэффициентом `min(ширина/1440, высота/900)`, от 1 до 1,8: левая колонка через `zoom`, телефон, карточки и орбиты через свой масштаб. Высота слайда задана как `calc(100svh / var(--ui))`, поэтому под `zoom` слайд по-прежнему ровно в высоту окна. На 1440×900 и меньше ничего не меняется.

## Подсказка «Живой кабинет»
Под телефоном, пока идёт автопоказ: кнопка с пульсирующей точкой открывает чистый экран входа и ставит курсор в поле почты. При наведении на телефон вокруг корпуса загорается красная обводка: видно, что по нему можно нажимать.

## Рабочая версия (/app)

`xronix.ru/app` открывает кабинет на весь экран, без презентации: слева панель с разделами и диалогами, справа те же экраны, что в телефоне (`src/app/DesktopApp.tsx`).
На узком экране панели нет, разделы внизу, как в телефоне. Перейти можно кнопкой «Открыть рабочую версию» на последнем слайде или ссылкой «Рабочая версия» в шапке.
Сборка одна: `npm run build` копирует `dist/index.html` в `dist/app.html`, GitHub Pages отдаёт его по адресу `/app`, а `App.tsx` по пути выбирает, что показать.
Вход общий с телефоном на презентации (токен в `localStorage`).

## Города и официальные условия банка

`src/data/cities.json` — локальный справочник 1102 городов с регионами из https://github.com/arbaev/russia-cities (данные 2023, получены 19.10.2026). Сохранены только географические названия и население для сортировки. Подсказки понимают пробелы вместо дефисов и е/ё. Населённый пункт вне справочника можно ввести вручную. `CityPicker` используется в анкете, профиле, вопросах ИИ и в чате без заполненного города. В настоящей сессии без города запрос не отправляется: сначала сохраняется выбранный город профиля. Существующий город пользователя не заменяется.

`src/data/alfaProducts.snapshot.json` — датированный снимок официальных страниц https://alfabank.ru/sme/profits/businesscredit/ и https://alfabank.ru/sme/profits/businessipoteka/. Начальные значения сверены по доступному индексированному тексту официальных страниц 19.10.2026. Обычная ставка и скидка хранятся отдельно; калькулятор использует обычную ставку выбранного продукта.

`npm run refresh:alfa` разбирает публичный HTML со стандартной проверкой TLS. Сравнительная таблица обязательна: рекламная ставка со скидкой не заменяет базовую. Только полный проверенный снимок атомарно заменяет предыдущий файл. `--html-dir` позволяет разобрать сохранённые официальные страницы.

Перед каждой сборкой GitHub Pages парсер пробует обновить условия. При сетевой ошибке, HTTP 403, проблеме сертификата или изменении структуры остаётся предыдущий снимок с прежней датой; workflow выводит предупреждение. Через 8 суток интерфейс предупреждает об устаревании. В текущей среде доступ ограничен: локально TLS-цепочка не доверена, с сервера с проверенной цепочкой НУЦ — HTTP 403. Успешный live-парсинг на 19.10.2026 **не подтверждён**; проверены представительные HTML-фикстуры и сохранение снимка при ошибке. Отключения проверки TLS нет.

Кнопки открывают официальную страницу в новой вкладке с `noopener noreferrer`. Анкетные данные и расчёты не передаются через URL. Это переход к условиям и заявке банка, а не отправка заявки из XRONIX.

Проверка: `npm test` (поиск городов, границы продуктов, адреса переходов, ошибки парсера), `npm run build` и ручной прогон в браузере. Демонстрационные данные презентации отделены от новых профилей.
