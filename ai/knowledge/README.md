# База знаний и банк фраз (раунд 3, задачи A1–A2)

Здесь живёт всё, что нужно **при разработке**, чтобы собрать два файла данных сервиса. В образ сервиса папка не входит, зависимости — `requirements.txt` рядом (`dataset/requirements.txt` + `openpyxl` + `gigachat`). Контракт — `contracts/ai.md`, раздел «База знаний и банк фраз», схема `contracts/schemas/knowledge.schema.json`. Лицензии — [`../LICENSES.md`](../LICENSES.md).

| Результат | Чем собирается | Откуда |
|---|---|---|
| `app/rules/data/knowledge.cities.json` | `python -m knowledge.build` | Росстат, OpenStreetMap (Overpass), справочник городов |
| `app/rules/data/phrases.json` | `python -m knowledge.generate_phrases` → вычитка → `--assemble` | GigaChat через API |

## База фактов — одна команда (из папки `ai`)

```sh
python -m knowledge.build              # Росстат + OSM: качает то, чего нет в knowledge/raw, и собирает базу
python -m knowledge.build --offline    # только из knowledge/raw, без сети: тот же файл байт в байт
```
- **Города:** 100 крупнейших по населению из `frontend/src/data/cities.json` плюс города из засева бэкенда и примеров контрактов (`common.target_cities`).
- **Зарплата** (`collect_rosstat.py`): файл Росстата `tab4-zpl-2025.xlsx`, последний полный год (2025), по региону города, `scope = region`.
- **Заведения** (`collect_osm.py`): по одному запросу Overpass на город. Город — точка `place=city|town` с этим названием внутри региона и административная граница, в которой она лежит («городской округ Самара», «Челябинский городской округ»). Теги считаются по отдельности и складываются в сферы при сборке (`build.SPHERES`):

  | Сфера | Теги OSM |
  |---|---|
  | `coffee` | `amenity=cafe` + `cuisine=coffee_shop`, `shop=coffee` |
  | `bakery` | `shop=bakery` |
  | `car_wash` | `amenity=car_wash` |
  | `clothing_store` | `shop=clothes` |
  | `beauty_salon` | `shop=beauty`, `shop=hairdresser` |
  | `pickup_point` | `shop=outpost` (постаматы `amenity=parcel_locker` считаются, но в сферу не входят) |

  Пауза 5 с между запросами, повтор при 429/5xx, кеш после каждого города: прерванный прогон продолжается с того же места. `--refresh` — собрать заново.
- **Проверка** при сборке: схема `cities_file`, правила `checkKnowledge` (источники описаны, города не повторяются), правдоподобие (зарплата 20–400 тыс. ₽, не больше одного заведения на 50 жителей). Тот же `check` гоняет `tests/test_knowledge.py`.

## Дополнительные факты (предложение команды)

```sh
python -m knowledge.collect_osm_places       # OSM: торговые центры, вузы и колледжи, офисные здания и БЦ (граница — из collect_osm)
python -m knowledge.collect_rosstat_extra    # Росстат: доходы на душу (2025), оборот розницы на душу (2024)
python -m knowledge.collect_fns              # ФНС: архив реестра МСП в knowledge/raw/fns/ -> counts.json (~6 мин)
```
Архив ФНС (2,2 ГБ) качается вручную по ссылке из `collect_fns.py` и в git не попадает; в репозитории — только подсчёт `raw/fns/counts.json`. Город в реестре — `Город`, а у городских округов — `Район` с типом «г.» (Нижний Новгород, Люберцы); одноимённые населённые пункты разных регионов различаются по коду региона, берётся тот, где больше записей.

Поля базы — по схеме `knowledge.schema.json` (`bea7160`): `footfall` (`malls`, `universities`, `business_centers`), `income_per_capita_rub` (руб./мес.), `retail_turnover_per_capita_rub` (годовой оборот на душу / 12), `registered_businesses` (по сферам; у пунктов выдачи своего ОКВЭД нет). `knowledge.build` включает поле, только если схема его знает. Покрытие по 100 городам: доходы, розница, ТЦ, вузы — 100; регистрации — 97–100 по сферам; бизнес-центров не меньше 10 — 80 городов.

Соответствие сфер и основного ОКВЭД (`collect_fns.OKVED`):

| Сфера | ОКВЭД |
|---|---|
| `coffee` | 56.30 — подача напитков |
| `bakery` | 10.71 — производство хлеба и мучных кондитерских изделий недлительного хранения; 47.24 — розничная торговля хлебом и выпечкой |
| `car_wash` | 45.20.3 — мойка автотранспортных средств |
| `clothing_store` | 47.71 — розничная торговля одеждой |
| `beauty_salon` | 96.02 — парикмахерские и салоны красоты |
| `pickup_point` | — (своего кода нет, факта нет) |

Новые слоты банка фраз (`registered_fact`, `places_malls`, `places_universities`, `places_business_centers`, `income_fact`, `retail_fact`, `ask_experience` в `phrase_rules._EXTRA`) используют подстановки контракта: числа — `{venues}` («около 80»), суммы — `{salary}` («59 000 ₽»), профиль ФНС — `{sphere}`. Слот включается, только если его подстановки есть в `PHRASE_PLACEHOLDERS` (`contracts/check.mjs`).

## Банк фраз

```powershell
$env:GIGACHAT_AUTH_KEY = "..."                                          # только в переменной окружения
python -m knowledge.generate_phrases                                    # слоты без ответа -> GigaChat -> phrases.review.md
python -m knowledge.generate_phrases --slots ask_city --refresh         # перегенерировать слоты (старый ответ -> *.prevN.json)
python -m knowledge.generate_phrases --assemble --reviewed-by "Имя"     # отмеченное [x] -> app/rules/data/phrases.json
```
- **Слоты и правила** — `phrase_rules.py`: 27 ситуаций (приветствие, не по теме, смена роли, «одобрят ли», вопросы о сфере, городе и своих деньгах, вступления, факты о конкуренции и зарплате, совет и риск по каждой из 6 сфер), обязательные и разрешённые подстановки.
- **Промпт** — `phrases_prompt.md`, **сырые ответы** — `raw/gigachat/<слот>.json` (модель, дата, сообщения, ответ, токены; ключа там нет).
- **Автопроверка** каждого варианта (`phrase_rules.check_variant`): правила `checkPhrases` из `contracts/check.mjs`, без цифр, только разрешённые подстановки, обязательные на месте, «около» не дублируется с `{venues}`, нет «в» перед `{in_city}`, `{source}` у зарплаты — «по данным {source}», вопрос со знаком «?», только «вы», без латиницы и обещаний кредита.
- **Вычитка** — `phrases.review.md`: `[x]` — в банк, `[ ]` — нет; после «   ← » пометка вычитки или причина автопроверки. `--assemble` ещё раз гоняет автопроверку, требует 5–15 вариантов на слот и проверяет схему `phrases_file`.

## Как сервис использует файлы

`app/rules/knowledge.py`: вариант выбирается детерминированно по хешу слота, первого сообщения человека и номера реплики. Фраза с подстановкой берётся, только если значение есть (факт есть в базе, заведений не меньше 10), иначе — вариант без неё или запасной текст без цифр. Факт о конкуренции — один раз за диалог (во вступлении к анкете или к плану), зарплата и совет по сфере — во вступлении к плану. Текст ответа не длиннее 600 символов.
