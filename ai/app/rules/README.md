# Экспертная система `/ai/consult` и `/ai/parse-need`

Собственная экспертная система на правилах, без нейросети, внешних API, ключей и GPU: словари, правила, разбор чисел, нормализация текста, база фактов о городах и банк фраз. Во время работы в сеть не ходит. Контракты — `contracts/ai.md` (в том числе раздел «База знаний и банк фраз»), схемы `consult.schema.json`, `parse-need.schema.json`, `knowledge.schema.json`.

История: в раундах 1–2 планировалась своя модель (LoRA Qwen3-1.7B). После раунда 2 обучение отменено, текущая реализация — эта система правил. Подробнее — [`../../LICENSES.md`](../../LICENSES.md).

| Файл | Что делает |
|---|---|
| `text.py` | нормализация, числа словами, суммы («800к», «1,5 млн», «полтора ляма», «миллиона два»), сроки |
| `extract.py` | исправление опечаток в ключевых словах, города (все падежи, 1102 города), сферы, ответы анкеты, свои деньги, намерения |
| `consult.py` | диалог: `state`, поправки, вопросы о недостающем, один раунд анкеты, `ready` |
| `knowledge.py` | база фактов и банк фраз: выбор варианта по хешу диалога, подстановки, факт о конкуренции один раз |
| `parse_need.py` | цель, сфера, город, сумма, срок, залог, `confidence` |
| `models.py` | pydantic-модели по схемам: проверка запроса (422) и своего ответа (502) |
| `build_data.py`, `data/` | снимок контрактов: справочники, шаблоны сфер, города с падежами (и `in` — «в Самаре»), условия «Старта» |
| `data/knowledge.cities.json` | факты о 100 городах: население, средняя зарплата по региону (Росстат), число заведений по 6 сферам (OpenStreetMap). Собирается `python -m knowledge.build` |
| `data/phrases.json` | банк фраз: 27 ситуаций, от 6 до 15 вариантов, сгенерирован GigaChat и вычитан. Собирается `knowledge/generate_phrases.py` |

## Запуск (из папки `ai`)

```sh
python -m venv .venv && .venv/Scripts/python -m pip install -r requirements.txt   # Linux: .venv/bin/python
.venv/Scripts/python -m uvicorn app.main:app --port 8001
```
Переменные окружения и ключи не нужны. В Docker всё нужное уже лежит в `app/rules/data`, контракты внутрь образа копировать не надо. Нет `knowledge.cities.json` или `phrases.json` — сервис работает на запасных текстах без цифр.

Контракт поменялся — пересобрать снимок (нужен `pymorphy3` из `dataset/requirements.txt`):
```sh
.venv/Scripts/python -m app.rules.build_data
```
Тест `tests/test_rules.py::Snapshot` падает, если снимок разошёлся с `contracts/`.

## Как работает `/ai/consult`

Порядок на каждое сообщение:
1. Опечатки в ключевых словах исправляются («етсь» → «есть», «тончо одорят» → «точно одобрят»). Города не трогаются.
2. Попытка сменить роль или показать инструкции, в том числе вместе с бизнес-запросом → `message`, `state` без изменений.
3. «Одобрят ли кредит», «даст ли банк кредит» → `message`. Обещаний нет, условия «Старта» берутся из `rules.start` и `products.demo.json` (не меньше 20 % своих денег, расчёт проекта, залог или поручитель).
4. Из сообщения извлекаются факты: сфера (прямо, ближайшая для бизнеса не из списка или неизвестный бизнес), город, свои деньги, ответы анкеты, «да/нет» на предложенную сферу. Тексты наших вопросов в ответе вида «Вопрос? Ответ» вырезаются, чтобы список сфер из вопроса не принимался за ответ.
5. Ничего по делу не нашлось или тема явно не про бизнес («какая погода в Самаре», даже с названием города) → приветствие или «не по теме» (`message`, `state` без изменений).
6. `state` обновляется. Известное значение меняется только при явной поправке («не Казань, а Самара», «поправлю», «передумал, лучше…») или как ответ на заданный вопрос. Смена сферы сбрасывает `answers`. Числа вне `min`–`max` не записываются.
7. Ответ, по порядку:
   - бизнес не из шаблонов → «Ближе всего — X. Считаем так?» или выбор из списка;
   - не хватает сферы, города или своих денег → вопросы ровно о них, в таком порядке;
   - вопросов анкеты в `history` ещё не было → один раунд анкеты (до 4 ещё не отвеченных вопросов); если всё уже отвечено — сразу `ready`;
   - иначе `ready`.

Тексты ответа и основных вопросов берутся из банка фраз (`knowledge.py`): вариант выбирается по хешу ситуации, первого сообщения человека и номера реплики — один диалог всегда звучит одинаково; чаты, начатые по-разному, — по-разному. Id чата в запросе нет, поэтому чаты с одинаковым первым сообщением получают одинаковые формулировки. Факты о городе:
- **конкуренция** — «в Самаре работает около 140 пекарен по данным OpenStreetMap»: один раз за диалог, во вступлении к анкете или к плану, только если в базе не меньше 10 заведений сферы;
- **зарплата по региону** и **совет или риск сферы** — во вступлении к плану.

Нет факта для города — фраза без цифр. Текст ответа не длиннее 600 символов (куски добавляются по важности, пока помещаются).

Что спрашивали, определяется по `history`: основные вопросы — по последней реплике ассистента, анкета — по любой реплике ассистента или по строкам «Вопрос? Ответ» в самом сообщении (как в примере контракта `consult.request.answers.json`). Полный `state` сам по себе не считается признаком пройденной анкеты. Если в последней реплике только вступительный текст без вопросов, недостающие основные поля считаются заданными вопросами.

## Ограничения

- **Не понимает смысл, только формулировки.** Новый оборот, которого нет в словарях, пропускается. Например, «хочу точку с капучино» не распознается как кофейня, и тогда человеку просто задаётся вопрос о сфере. Для неизвестного ответ всегда безопасный: вопрос или `message`, `null` в parse-need.
- **Опечатки** исправляются только в ключевых словах и только на одну букву, первая буква должна совпадать. Слова из трёх букв не исправляются («ноь» вместо «ноль»).
- **Город без предлога.** Если название — обычное слово или фамилия («Бор», «Остров», «Короча» / «короче», «Пугачёв»), а город небольшой, он принимается только после «в / из / город» или как ответ на вопрос «В каком городе?». Нечёткий поиск по опечатке в названии малого города тоже требует предлога.
- **Поправки** узнаются по маркерам («не X, а Y», «поправлю», «ошибся», «передумал», «лучше», «другой»). Без маркера новое значение не перезаписывает старое: исключение — первое сообщение чата (город из профиля можно переназвать) и ответ на прямой вопрос.
- **Несколько сумм в одной фразе:** свои деньги — сумма рядом со словами «есть / своих / бюджет / накопил / вложить» (до или после неё: «300 тысяч свои»); сумма с «не» — старая («своих не миллион, а 800 тысяч»). В первой реплике единственная сумма без признаков кредита, чека или выручки тоже считается своими («Питер, кофейня, 1 млн»). В parse-need выручка и доход («выручка 2 млн в месяц») не считаются суммой запроса; при нескольких оставшихся разных суммах берётся первая с `confidence = 0.6`, чтобы фронт подсветил поле.
- **Ответ вне min–max** не записывается, бэкенд возьмёт `default`. Так и было в датасете раунда 1.
- **«Что спрашивали»** восстанавливается по `history`. Если бэкенд положит туда не наш текст вопросов, анкета может быть задана ещё раз (это безопасно, но лишний шаг).
- **Факты только о 100 городах** базы. Для остальных городов диалог идёт без цифр. Данные OSM неполные (например, кофейни часто отмечены просто как кафе), поэтому в тексте только «около N».
- **Фразы ограничены банком:** 328 вариантов на 27 ситуаций. Свободного текста система не пишет.

## Что передать Илье

1. `/ai/respond` и GigaChat из сервиса удалены: бэкенд получает `404 NOT_FOUND` и, как и раньше на `503`, ведёт запасной диалог. `/ai/summarize` остаётся, работает без модели.
2. Переменные окружения, `.env` и сертификаты сервису не нужны; в образ входит только `app/`.
3. В `history` для `/ai/consult` по-прежнему класть реплику ассистента так, как её видел человек: `text`, затем каждый вопрос и варианты (`Вопрос? Варианты: А / Б`). По ним определяется, что спрашивали и звучал ли уже факт о конкуренции.
4. Тексты ответов теперь до 600 символов (`consult.schema.json`).
5. Время ответа ~2 мс, таймаут бэка 10 с с огромным запасом.
