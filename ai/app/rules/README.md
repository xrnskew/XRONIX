# Правиловая система `/ai/consult` и `/ai/parse-need`

Работает без внешних моделей, API, ключей и GPU: словари, правила, разбор чисел и нормализация текста. Контракты — `contracts/ai.md`, схемы `consult.schema.json` и `parse-need.schema.json`.

| Файл | Что делает |
|---|---|
| `text.py` | нормализация, числа словами, суммы («800к», «1,5 млн», «полтора ляма», «миллиона два»), сроки |
| `extract.py` | исправление опечаток в ключевых словах, города (все падежи, 1102 города), сферы, ответы анкеты, свои деньги, намерения |
| `consult.py` | диалог: `state`, поправки, вопросы о недостающем, один раунд анкеты, `ready` |
| `parse_need.py` | цель, сфера, город, сумма, срок, залог, `confidence` |
| `models.py` | pydantic-модели по схемам: проверка запроса (422) и своего ответа (502) |
| `build_data.py`, `data/` | снимок контрактов: справочники, шаблоны сфер, города с падежами, условия «Старта» |

## Запуск (из папки `ai`)

```sh
python -m venv .venv && .venv/Scripts/python -m pip install -r requirements.txt   # Linux: .venv/bin/python
.venv/Scripts/python -m uvicorn app.main:app --port 8001
```
`GIGACHAT_AUTH_KEY` не нужен. Без ключа сервис стартует сразу: `/ai/consult` и `/ai/parse-need` работают, старый `/ai/respond` отвечает `503 AI_UNAVAILABLE`. В Docker всё нужное уже лежит в `app/rules/data`, контракты внутрь образа копировать не надо.

Контракт поменялся — пересобрать снимок (нужен `pymorphy3` из `dataset/requirements.txt`):
```sh
.venv/Scripts/python -m app.rules.build_data
```
Тест `tests/test_rules.py::Snapshot` падает, если снимок разошёлся с `contracts/`.

## Как работает `/ai/consult`

Порядок на каждое сообщение:
1. Опечатки в ключевых словах исправляются («етсь» → «есть», «тончо одорят» → «точно одобрят»). Города не трогаются.
2. Попытка сменить роль или показать инструкции, в том числе вместе с бизнес-запросом → `message`, `state` без изменений.
3. «Одобрят ли кредит» → `message`. Обещаний нет, условия «Старта» берутся из `rules.start` и `products.demo.json` (не меньше 20 % своих денег, расчёт проекта, залог или поручитель).
4. Из сообщения извлекаются факты: сфера (прямо, ближайшая для бизнеса не из списка или неизвестный бизнес), город, свои деньги, ответы анкеты, «да/нет» на предложенную сферу. Тексты наших вопросов в ответе вида «Вопрос? Ответ» вырезаются, чтобы список сфер из вопроса не принимался за ответ.
5. Ничего по делу не нашлось → приветствие или «не по теме» (`message`, `state` без изменений).
6. `state` обновляется. Известное значение меняется только при явной поправке («не Казань, а Самара», «поправлю», «передумал, лучше…») или как ответ на заданный вопрос. Смена сферы сбрасывает `answers`. Числа вне `min`–`max` не записываются.
7. Ответ, по порядку:
   - бизнес не из шаблонов → «Ближе всего — X. Считаем так?» или выбор из списка;
   - не хватает сферы, города или своих денег → вопросы ровно о них, в таком порядке;
   - вопросов анкеты в `history` ещё не было → один раунд анкеты (до 4 ещё не отвеченных вопросов); если всё уже отвечено — сразу `ready`;
   - иначе `ready`.

Что спрашивали, определяется по `history`: основные вопросы — по последней реплике ассистента, анкета — по любой реплике ассистента или по строкам «Вопрос? Ответ» в самом сообщении (как в примере контракта `consult.request.answers.json`). Полный `state` сам по себе не считается признаком пройденной анкеты. Если в последней реплике только вступительный текст без вопросов, недостающие основные поля считаются заданными вопросами.

- неполные данные и город из профиля;

## Ограничения

- **Не понимает смысл, только формулировки.** Новый оборот, которого нет в словарях, пропускается. Например, «хочу точку с капучино» не распознается как кофейня, и тогда человеку просто задаётся вопрос о сфере. Для неизвестного ответ всегда безопасный: вопрос или `message`, `null` в parse-need.
- **Опечатки** исправляются только в ключевых словах и только на одну букву, первая буква должна совпадать. Слова из трёх букв не исправляются («ноь» вместо «ноль»).
- **Город без предлога.** Если название — обычное слово или фамилия («Бор», «Остров», «Короча» / «короче», «Пугачёв»), а город небольшой, он принимается только после «в / из / город» или как ответ на вопрос «В каком городе?». Нечёткий поиск по опечатке в названии малого города тоже требует предлога.
- **Поправки** узнаются по маркерам («не X, а Y», «поправлю», «ошибся», «передумал», «лучше», «другой»). Без маркера новое значение не перезаписывает старое: исключение — первое сообщение чата (город из профиля можно переназвать) и ответ на прямой вопрос.
- **Несколько сумм в одной фразе:** свои деньги — первая сумма рядом со словами «есть / своих / бюджет / накопил / вложить». В parse-need при нескольких разных суммах берётся первая с `confidence = 0.6`, чтобы фронт подсветил поле.
- **Ответ вне min–max** не записывается, бэкенд возьмёт `default`. Так и было в датасете раунда 1.
- **«Что спрашивали»** восстанавливается по `history`. Если бэкенд положит туда не наш текст вопросов, анкета может быть задана ещё раз (это безопасно, но лишний шаг).
- **Тексты ответов шаблонные**, без вариативности. Если нужны живые формулировки, это работа модели в раунде 2.

## Что передать Илье

1. Новые методы: `POST /ai/consult` и `POST /ai/parse-need` в существующем сервисе `ai` (`app/main.py`), строго по контракту. Ошибки: `422 VALIDATION_ERROR` на кривой запрос, `502 AI_BAD_RESPONSE`, если вдруг собственный ответ не прошёл схему.
2. Ключ GigaChat сервису больше не обязателен: он стартует без него, `/ai/respond` в этом случае даёт `503`.
3. В `history` для `/ai/consult` класть реплику ассистента так, как её видел человек: `text`, затем каждый вопрос и его варианты построчно (`Вопрос? Варианты: А / Б`). По ним определяется, что спрашивали.
4. Ответ на анкету фронт уже шлёт строками «Вопрос? Ответ». Так и оставить: эти строки разбираются точнее всего.
5. Время ответа ~10 мс, таймаут бэка в 10 с с огромным запасом.
