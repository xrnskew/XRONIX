### A. База знаний и банк фраз для экспертной системы — главное в раунде

Цель: чат отвечает живо и конкретно — «в Самаре около 100 пекарен по данным OpenStreetMap», разные формулировки, советы по сфере — но по-прежнему без нейросети, ключей и сети во время работы. Контракт: `contracts/ai.md`, раздел «База знаний и банк фраз», схема `contracts/schemas/knowledge.schema.json`, примеры `contracts/examples/knowledge.*.json`.

**A1. Сборщики фактов** — `ai/knowledge/collect_*.py`, результат `ai/app/rules/data/knowledge.cities.json` по схеме `cities_file`.
- Города: 100 крупнейших по населению из `cities.json`, плюс все города из засева и примеров.
- Население — уже есть в `cities.json`. Если обновляете из Wikidata (CC0), укажите источник.
- Средняя зарплата по региону — Росстат или ЕМИСС, последний полный год, `scope = region`.
- Число заведений по 6 сферам — OpenStreetMap через Overpass API (ODbL). Предлагаемые теги, уточнить по факту:

  | Сфера | Теги OSM |
  |---|---|
  | `coffee` | `amenity=cafe` + `cuisine=coffee_shop`, `shop=coffee` |
  | `bakery` | `shop=bakery` |
  | `car_wash` | `amenity=car_wash` |
  | `clothing_store` | `shop=clothes` |
  | `beauty_salon` | `shop=beauty`, `shop=hairdresser` |
  | `pickup_point` | `shop=outpost`, `amenity=parcel_locker` |

  Данные OSM неполные, поэтому в тексте только «около N» и «по данным OpenStreetMap». Overpass не нагружать: пауза между запросами, кеш сырых ответов, одна сборка — один прогон.
- Нельзя: парсить Авито, ЦИАН, 2ГИС, Яндекс Карты и другие сайты, условия которых запрещают сбор. Генерировать факты языковой моделью — тоже нельзя.
- Сборка воспроизводится одной командой. Сырые ответы источников — в `ai/knowledge/raw/` (или скачиваются заново), итоговый файл коммитится. Дата сборки — в `generated_at`.

**A2. Банк фраз через GigaChat** — `ai/knowledge/generate_phrases.py`, результат `ai/app/rules/data/phrases.json` по схеме `phrases_file`.
- Ключ — от Саши, с призовыми пакетами токенов, через переменную `GIGACHAT_AUTH_KEY`. В репозиторий, логи и отчёт ключ не попадает.
- Слоты — на все ситуации диалога `/ai/consult`, от 5 до 15 вариантов на слот:
  - приветствие, «не по теме», попытка сменить роль, «одобрят ли кредит» (отказ обещать);
  - вопросы о сфере, городе, своих деньгах; предложение ближайшей сферы; вступление к анкете; вступление к готовому плану;
  - факты: конкуренция в городе, зарплата по региону как ориентир расходов на персонал;
  - советы и риски по каждой из 6 сфер.
- Правила для фраз — `ai.md`, правила 3–4 раздела: без цифр, числа только через `{подстановки}`, без обещаний кредита. Промпт генерации и сырые ответы GigaChat — в репозитории, рядом со скриптом.
- Каждый вариант проходит автоматическую проверку (`checkPhrases` в `contracts/check.mjs` — образец) и вычитку человеком. В `generated` — модель GigaChat, дата и кто вычитал.

**A3. Подключение к сервису.**
- Вариант фразы выбирается детерминированно, например по хешу чата и номера реплики: тесты и оценка повторяются один в один.
- Факт подставляется, только если он есть в базе для этого города. Иначе — вариант без цифр.
- Факт о конкуренции — один раз за диалог, когда известны сфера и город. Удобно — во вступлении к анкете или к готовому плану.
- Тексты ответов — до 600 символов (`consult.schema.json`, `reply.schema.json`).
- Оценщик: метрика «придуманные суммы» засчитывает числа из базы фактов как разрешённые. Остальные метрики и пороги 13.3 — без изменений.
- Тесты: все фразы проходят схему и `checkPhrases`; каждая подстановка разрешается; число в ответе совпадает с базой фактов; без базы сервис отвечает фразами без цифр; ответы прежних сценариев по-прежнему проходят схемы.

**A4. Независимая проверка правил** — задание Дане из `backend/ROUND2_EXTERNAL_TASKS.md`: новый ручной набор 50–100 фраз, первый результат неизменённых правил — до любых доработок.

**A5. Документы Дани.** `ai/LICENSES.md` и `ai/app/rules/README.md`: источники фактов и их лицензии, GigaChat как инструмент генерации фраз, история с Qwen — как отменённый план.
