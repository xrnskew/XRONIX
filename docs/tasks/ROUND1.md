## Даня · ветка `ai`

**Цель раунда:** понять, на чём учимся, и собрать датасет для `/ai/parse-need`.

1. **Первым делом лицензии.** Разрешают ли условия GigaChat API использовать ответы для обучения других моделей? Есть ли у GigaChat 3 открытые веса и под какой лицензией? Итог — короткая записка в `ai/LICENSES.md` со ссылками. Если GigaChat API нельзя, генерируем данные открытой моделью.
2. Выбрать базовую модель до ~2 млрд параметров с открытой лицензией (например, Qwen3-1.7B, Apache 2.0). Записать в ту же записку.
3. Генератор датасета `ai/dataset/generate.py` строго по `contracts/ai.md` → «Правила для модели и датасета» и `parse-need.schema.json`. Разнообразие: все цели и сферы из `dictionaries.json`, города из `frontend/src/data/cities.json`, суммы цифрами и словами («полтора ляма», «800к», «2,5 млн»), сроки словами, опечатки, разговорный стиль, запросы без суммы, без города, не про бизнес.
4. Каждый пример проходит схему, иначе выбрасывается. Генерировать так, чтобы правильный ответ был известен заранее (сначала выбрать значения полей, потом попросить модель написать текст под них), а не наоборот: тогда разметка гарантированно верная.
5. 2–3 тыс. примеров для обучения и отдельно 200+ для отложенной выборки. Отложенная выборка генерируется отдельно и не используется при обучении.
6. Скрипт оценки `ai/dataset/evaluate.py`: точность по каждому полю для любой функции «текст → ответ». Прогнать на простом базовом решении (регулярки), чтобы было с чем сравнивать модель.

**Готово, когда:** записка о лицензиях, датасет и отложенная выборка лежат в репозитории, `evaluate.py` печатает точность базового решения по полям.

## Саша · ветка `frontend`

**Цель раунда:** клиент проходит от компании до поданной заявки на моках фронта по контрактам v2.

1. Моки v2 в `src/api/mock.ts` на примерах из `contracts/examples/`: компании, подбор, заявки со сменой статусов по таймеру.
2. Экран «Компания»: ввод ИНН с проверкой контрольной суммы на лету (`validInn` из `contracts/check.mjs`), карточка из реестра, выбор роли в компании, загрузка доверенности, если роль её требует.
3. Мастер потребности: поле «Опишите своими словами» (`POST /api/needs/parse`, при пустом ответе просто идём дальше) → цель → сумма и срок → залог. Подсветка полей с `confidence < 0.7`.
4. Подбор продукта: карточки «подходит / не подходит, потому что…», платёж, кнопка «Подать заявку» только при `can_apply`.
5. Форма заявки: предзаполнение, финансы за 12 мес., залог для `secured`, согласие на БКИ, автосохранение черновика, список `missing_fields` перед подачей.
6. Экран заявки: таймлайн, блоки «Что сейчас происходит» / «Что нужно от вас» из `status_info`, опрос раз в 2 с в автоматических статусах.
7. Навигация `/app`: Заявки · Новая заявка · Лента · Профиль. Чат убрать из меню, код не удалять. Аналитик после входа уходит на `/bank` (заглушка).

**Готово, когда:** на моках фронта путь «ИНН → потребность → подбор → заявка → подана → статус меняется сам» проходит без ошибок в консоли, `npm test` и `npm run build` зелёные.
