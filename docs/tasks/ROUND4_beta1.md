## Калибровка расчёта (пункты 2 и 3): что сделано
- `contracts/templates/city_wages.v1.json`: средняя начисленная зарплата региона города (Росстат, 2025) для 100 городов и `default_avg_salary_rub = 65 000` для остальных; `monthly.salary_share` у каждой сферы (кофейня 0,5, пекарня 0,55, автомойка 0,5, одежда 0,5, салон красоты 0,55, пункт выдачи 0,4) вместо `salary_per_staff`.
- Зарплата сотрудника = `round(средняя зарплата региона × salary_share)`, с взносами 30%. Коэффициент города `k` теперь влияет только на аренду.
- Расхождений между расчётом фронта и backend нет (486 случаев). Backend выложен в ветку `backend`, на production нужна выкладка (см. дополнение в `backend/deploy/ROUND4_RELEASE_PLAN.md`).
- Эти значения оценочные (доля от средней по региону, а не рыночная зарплата конкретной должности). Если нужна ещё более точная привязка, нужен источник по должностям (например, данные Росстата по профессиям); пока не берём.

## Даня
- «Без сотрудников», «ноль сотрудников», «работаю сам» → `staff = 0` в анкете.
- Ответы чата на «не знаю» и «хочу что-то прибыльное»: сейчас повторяется вопрос про сферу. Нужен хотя бы короткий ответ с примерами («Например, кофейня в Самаре…»).
- Копия заметки о демо-продукте в `ai/app/rules/data/rules.json` всё ещё говорит «не продукт Альфа-Банка»; синхронизировать с `contracts/products.demo.json`.

## На будущее (пункт 11)
Маленькая языковая модель в Docker снимет часть шаблонности, но противоречит нашему заявлению «без нейросетей, без платных API» и увеличит образ и память. До сдачи не делаем. Если вернёмся: локальная модель только для перефразирования ответов экспертной системы (факты и числа остаются у правил), отдельный сервис, выключатель, замер памяти и размера образа.
