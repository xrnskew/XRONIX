# Раунд 1 — дополнение для бэкенда (Илья, делит с Даней)

Решения команды от 20 октября:
1. **Чат остаётся** и становится главным входом для тех, кто ещё выбирает бизнес. Модель Дани ведёт диалог, цифры плана считает бэкенд по шаблонам.
2. **Демо-продукт «Старт»** для тех, у кого бизнеса ещё нет. Настоящие продукты Альфы не трогаем, правило 9 месяцев для них остаётся.

Что изменилось в контрактах (`npm run check` зелёный; в `dev` попадает вместе с этим файлом):
- `contracts/conveyor.md` — разделы «Чат подбора бизнеса», «Будущий ИП», «Демо-продукт «Старт»».
- `contracts/ai.md` — новый главный метод `/ai/consult`, схема `schemas/consult.schema.json`, примеры `examples/consult.*.json`.
- `contracts/products.demo.json` — параметры «Старта», `rules.start` в `rules/credit_rules.v1.json`.
- В `common.schema.json` добавлены `product_id: start`, `collateral_kind: guarantor`, `company_kind: person`, `company_status: not_registered`, причины отказа `own_funds_low` и `plan_required`.
- `match_item` получил обязательное поле `demo`; у демо-продукта `url = null`.
- У компании будущего ИП `ogrn`, `registered_at`, `okved` — `null`.

Эталон логики — фронтовый мок, он проходит все сценарии в браузере: `frontend/src/lib/creditRules.ts` (скоринг и решение, включая «Старт»), `frontend/src/api/mock.ts` (диалог чата без модели), `frontend/tests/conveyor.test.mjs` (тесты, которые бэкенд должен повторить).

## Добавить к задачам раунда 1

### Илья — конвейер
1. `POST /api/companies` с `future: true` и личным ИНН (12 цифр) создаёт компанию `kind = person`, `status = not_registered`, `member_role = owner`, имя — из профиля пользователя. ЕГРЮЛ для неё не вызывается, БКИ — по личному ИНН.
2. Полнота заявки для `person`: из финансов обязательны только `loan_payments_monthly_rub`. Залог (любой `kind`, включая `guarantor`) обязателен для `secured` и `start`.
3. Подбор (`/api/products/match`) отдаёт пять продуктов, включая `start` с `demo = true`. Для `person` продукты Альфы не подходят с причиной «нужны зарегистрированные ИП или компания». Для `start` проверить наличие плана и долю своих денег не меньше 20%. Тексты причин — как во фронтовом моке.
4. Стоп-факторы, скоринг и решение для `start` — по `rules.start` и `docs/CONVEYOR.md`, раздел 6.4. При одобрении или встречном предложении для `person` добавить `rules.start.condition_text` последней строкой в `offer.explanation`.

### Илья — чат подбора бизнеса (можно во втором раунде, если не успеваешь)
5. Хранить `state` чата: сфера, город, свои деньги, ответы анкеты. Город по умолчанию — из профиля.
6. На сообщение звать `/ai/consult` с таймаутом. `questions` и `message` отдавать в чат как есть. На `ready` считать план по `contracts/templates.md`, сохранять и отвечать `type = plan` с `plan_id`.
7. Без модели вести диалог самому: сфера (текстом, с подсказкой из шаблонов) → город → свои деньги → план с ответами по умолчанию. Так же, как `sendMessage` во фронтовом моке.

### Даня — модель
8. **Главный датасет теперь для `/ai/consult`**, а `/ai/parse-need` — второй. Правила для модели и датасета — `contracts/ai.md`, раздел про `/ai/consult`: модель заполняет `state` и задаёт до 4 уточняющих вопросов за раз, но никогда не называет суммы и не обещает кредит.
9. Датасет диалогов: идея своими словами → ожидаемый `state` → ожидаемый тип ответа. Сначала выбирать `state`, потом генерировать реплики под него, как и для `parse-need`. Отдельно — сообщения не про бизнес и попытки сменить роль: ожидаемый ответ — `message`, `state` без изменений.
10. Метрики на отложенной выборке: точность каждого поля `state`, точность типа ответа (`questions`, `message`, `ready`), доля ответов, где модель назвала сумму, которой не было в тексте человека (должна быть 0).
