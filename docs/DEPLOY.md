# Деплой фронта: GitHub Pages + домен с reg.ru + DNS в Яндекс Облаке

Фронт собирается GitHub Actions (`.github/workflows/deploy-frontend.yml`) и публикуется на GitHub Pages. Бэкенд и ИИ-сервис живут отдельно в Яндекс Облаке.
Схема адресов:

| Адрес | Что | Где |
|---|---|---|
| `https://xronix.ru` (и `www`) | Сайт-презентация с кабинетом | GitHub Pages |
| `https://api.xronix.ru` | Бэкенд Ильи | ВМ или балансировщик в Яндекс Облаке |

Репозиторий публичный: в нём не должно быть паролей и токенов. Всё секретное только в `.env` на сервере.

## 1. Где сейчас DNS домена
Открой личный кабинет reg.ru → Домены → твой домен → «DNS-серверы и управление зоной».
Или в терминале: `nslookup -type=NS xronix.ru`.

- `ns1.reg.ru`, `ns2.reg.ru`: записи правятся в reg.ru. Делегировать в Яндекс не обязательно, можно сразу идти к шагу 3 и добавить записи там.
- `ns1.yandexcloud.net`, `ns2.yandexcloud.net`: зона уже в Cloud DNS, записи правятся в консоли Яндекс Облака.

Хочешь управлять зоной из Яндекс Облака: сначала создай там публичную зону (Cloud DNS → Создать зону → `xronix.ru.`), перенеси нужные записи, и только потом в reg.ru поменяй NS на `ns1.yandexcloud.net` и `ns2.yandexcloud.net`. Если сменить NS раньше, чем зона заполнена, сайт и почта домена перестанут открываться. Обновление NS занимает от часа до суток.

## 2. Включить GitHub Pages (нужен доступ владельца репозитория)
1. `Settings → Pages → Build and deployment → Source: GitHub Actions`.
2. `Settings → Environments → github-pages → Deployment branches`: добавь `main`, `dev` и `frontend` (по умолчанию разрешён только `main`, и деплой из других веток упадёт).
3. `Actions → Deploy frontend to GitHub Pages → Run workflow`, выбери ветку. Через пару минут сайт будет на `https://xrnskew.github.io/XRONIX/`.

Деплоится последний запуск, ветки не публикуются параллельно. Для финальной сдачи публикуй из `main`.

## 3. Привязать домен (домен xronix.ru, NS уже указывают на Яндекс Облако)
Зона должна существовать в Cloud DNS, иначе домен не открывается вообще.

1. Консоль Яндекс Облака → нужный каталог → Cloud DNS → «Создать зону»: зона `xronix.ru.` (с точкой на конце), тип «Публичная».
2. В зоне «Создать запись» (TTL 600):

| Имя | Тип | Значение |
|---|---|---|
| пусто (сам домен) | `A` | `185.199.108.153`, `185.199.109.153`, `185.199.110.153`, `185.199.111.153` (четыре значения в одной записи) |
| пусто | `AAAA` | `2606:50c0:8000::153`, `2606:50c0:8001::153`, `2606:50c0:8002::153`, `2606:50c0:8003::153` |
| `www` | `CNAME` | `xrnskew.github.io.` |

3. GitHub: `Settings → Pages → Custom domain` → `xronix.ru` → Save. GitHub сам перенаправит `www` на основной адрес. Когда проверка DNS пройдена, включи `Enforce HTTPS` (сертификат Let's Encrypt выпускается автоматически, от минут до нескольких часов).
4. Проверка (результат не зависит от кеша провайдера): `nslookup xronix.ru ns1.yandexcloud.net` должен вернуть адреса 185.199.x.x.

DNSSEC в reg.ru не включай: ключи нужно сначала создать в Яндекс Облаке, иначе домен перестанет открываться.
Желательно подтвердить домен в аккаунте GitHub (`Settings → Pages → Add a domain`, добавляется TXT-запись в зону), чтобы им не завладел чужой репозиторий.

## 4. Бэкенд на поддомене api
1. В Яндекс Облаке получи публичный IP ВМ (или адрес балансировщика), в DNS-зоне добавь `api` `A` → этот IP.
2. **HTTPS обязателен**: сайт на HTTPS не может ходить на `http://` API, браузер заблокирует запросы. Варианты: Certificate Manager + Application Load Balancer либо Caddy или nginx с Let's Encrypt на самой ВМ.
3. **CORS на бэкенде** (скажи Илье): разрешить `Origin: https://app.xronix.ru` (и `http://localhost:5173` для разработки), заголовок `Authorization`, методы `GET, POST, PATCH, OPTIONS`. Без этого кабинет на Pages не сможет обращаться к `api.xronix.ru`.
4. В репозитории: `Settings → Secrets and variables → Actions → Variables`:
   - `VITE_API_URL` = `https://api.xronix.ru`
   - `VITE_USE_MOCKS` = `false`
   Переменные `VITE_*` попадают в публичный JS, секретов в них быть не должно. Пока бэкенда нет, не задавай их: сайт соберётся на моках и будет полностью рабочим.
5. Перезапусти workflow, чтобы сборка подхватила переменные.
