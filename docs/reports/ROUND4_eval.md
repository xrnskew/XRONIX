## Сообщение для сбора — пользователь пересылает участникам

> Привет! Проверяем, понимает ли наш бизнес-помощник обычную человеческую речь. Нужны участники, которые не видели его правил, обучающих примеров и тестов. Напиши самостоятельно, без нейросети, по 2–3 фразы для двух ситуаций:
>
> 1. Ты обсуждаешь открытие своего дела с помощником. Напиши так, как написал бы в реальном чате: что хочешь открыть, где, какие есть деньги или что ещё важно. Можно знать не всё.
> 2. Ты обращаешься за финансированием бизнеса. Свободно сформулируй потребность: на что деньги, сколько и на какой срок — если это известно.
>
> Пиши своими словами, не исправляй специально разговорный стиль и случайные опечатки. Можно добавить очень короткое сообщение или сообщение совсем на другую тему. Не смотри чужие ответы до отправки. Рядом отдельно напиши, что ты имел в виду и чего ожидал от помощника. Не включай личные данные, реквизиты или сведения реальных клиентов. Укажи любой псевдоним и подтверди, что не видел правил/тестов и не использовал генератор текста. Спасибо!

Собрать **30–50 сообщений, по 15–25 для каждой ситуации**. Не отбирать только удобные фразы. Если пришло больше, до просмотра ответов сервиса зафиксировать первые 15–25 по времени в каждой группе. Записать, кто собирал, даты сбора и подтверждения независимости. Псевдонимы вместо ФИО.

## Воспроизводимый прогон

Из корня репозитория, подготовить отдельный каталог вне рабочей копии:

```sh
mkdir /tmp/xronix-independent-eval
git archive 311e860 ai | tar -x -C /tmp/xronix-independent-eval
# Из /tmp/xronix-independent-eval/ai, с зависимостями из ai/requirements.txt:
python -m uvicorn app.main:app --host 127.0.0.1 --port 18001
```

Сервис не менять до завершения оценки. Записать команду запуска, версии зависимостей и SHA архива. Далее из корня репозитория:

```sh
python backend/tools/evaluate_round4.py capture \
  --cases docs/reports/artifacts/ROUND4_eval_cases.json \
  --output docs/reports/artifacts/ROUND4_eval_raw.json \
  --base-url http://127.0.0.1:18001
```

Инструмент фиксирует SHA-256 входного файла, исходный текст, полный HTTP-запрос, статус, буквальное тело ответа и длительность. Он не генерирует фразы и не оценивает смысл автоматически. Выходной файл создаётся исключительно новым; повторная запись запрещена. При сбое не скрывать первый результат повторным запросом. Метаданные SHA предполагают запуск указанного архива: сам HTTP API не сообщает версию сервиса, инструмент её удалённо не удостоверяет.

Оригинал raw сохранить неизменным; для разметки сделать копию `ROUND4_eval_reviewed.json`. Для каждой строки человек заполняет `correct` (true/false), `reviewer` (псевдоним), `reason` (что верно/ошибка). Даня до этого набор не получает.

Критерий: корректно поняты все явно указанные поля, неизвестные не придуманы, реплика уместна; для постороннего сообщения — возврат к теме без изменения состояния. Для consult допустим уточняющий вопрос, когда данные неоднозначны или неполны. Для parse-need сверять назначение, сумму, срок и остальные явно названные поля по контракту. HTTP-ошибка/недоступность — неуспех с отдельной причиной. Спорную трактовку сверить с намерением автора, не менять исходную фразу.

```sh
python backend/tools/evaluate_round4.py summary \
  docs/reports/artifacts/ROUND4_eval_reviewed.json
```

Процент = число верных / все фразы соответствующего endpoint × 100. Пока не размечена каждая строка, инструмент не выдаёт процент. В итог добавить таблицу всех фраз со ссылками на полные ответы, а также число ошибок транспорта отдельно. Дополнительные диалоговые пробы не смешивать с этим набором.
