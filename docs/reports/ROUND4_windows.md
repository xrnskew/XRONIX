# ROUND4: первый запуск XRONIX на Windows

Дата проверки: 22 октября 2026. Проверка проведена в новом клоне ветки `backend` по адресу `http://localhost:8080/app`. Исходный код до первого `docker compose up` не изменялся; `frontend/` и `ai/` не редактировались. Публичные сайты и API не использовались.

## Машина и подготовка

- ОС: Windows 11 Pro x64, версия 10.0.26200, build 26200.
- CPU: AMD Ryzen 5 7500F, 6 ядер / 6 логических процессоров; аппаратная виртуализация включена.
- RAM: 33,120,168 KiB видимой памяти (~31.59 GiB); до установки Docker свободно 21,665,024 KiB (~20.66 GiB). Перед сборкой после старта WSL/Docker свободно 15,882,524 KiB (~15.15 GiB).
- WSL: 3.0.3.0, Ubuntu, WSL 2; kernel 6.1.54.1.
- Git: 2.53.0.windows.2.
- Docker Desktop: 4.96.1 (244132), per-user install, WSL 2 backend; Docker Engine 29.9.2; Compose v5.6.0.
- Установщик загружен с официального домена Docker. Загрузка: 64.340 с, 651,120,048 байт. Установка по журналу установщика: 19.308 с, `Installation succeeded`. Установка инструмента не включена в таймер проекта. SHA-256 установщика и подробности в `artifacts/ROUND4_windows/docker-install-measurement.json`.
- Docker до сборки: `docker system df` — 0 images, 0 containers, 0 volumes, 0 build cache; `docker images` пуст. Кэш холодный.

## Репозиторий и первый запуск

- Команда клонирования: `git clone --branch backend --single-branch https://github.com/xrnskew/XRONIX.git backend-first-run`.
- Ветка: `backend`; фактический SHA: `083582ae500d2defa222a980b216255cd3ad9a5a` (совпадает с заданным `083582a`). Статус перед запуском: чистый.
- Прочитаны корневой `README.md`, `docs/reports/ROUND4_backend.md`, корневой `docker-compose.yml`, `backend/README.md`. Файлов `AGENTS.md` в клоне нет.
- Команда конфигурации: `docker compose config --quiet` — exit code 0.
- Первая попытка: `docker compose up -d --build --wait --wait-timeout 600` — exit code 0; все 4 сервиса healthy. Неудачных попыток и исправлений исходников не было.

## Браузерные сценарии

Проверки проходили в UI без моков на `http://localhost:8080/app`. Успешные сценарии, суммы, статусы и найденный дефект подробно перечислены в `artifacts/ROUND4_windows/browser-findings.md`.

С AI: успешный вход клиента и аналитика; решения по «Вектору» (встречное предложение 10 млн ₽ / 60 мес.) и Лебедеву (запрос финансовых данных); чат создал план пекарни в Самаре и дал выбрать «Старт» для будущего ИП с поручителем; 40 млн ₽ без залога на 36 мес. для «Северной выпечки» подходили только по господдержке, была видна дата акции 15 ноября; заявка `Z-2026-000008` прошла до `manual_review`, в скоринге аналитика было поручительство Корпорации МСП +8.

Без AI: остановлен только сервис `ai` этого проекта командой `docker compose stop ai`; backend, web и integrations-mock оставались healthy, backend `/health` вернул `{"status":"ok"}`. Оба демо-входа прошли. Новый чат с заданной фразой успешно выдал план, в финансах указано 900,000 ₽ своих средств (расчёт старта — 3,058,000 ₽); создание задания до успешного завершения — 4.087572 с по timestamps SQLite. «Старт» был единственным подходящим продуктом для будущего ИП с поручителем. Господдержка подобралась единственной для новой заявки `Z-2026-000009`; она дошла до `manual_review`, аналитик увидел +8. Первый том не сбрасывался, решения повторялись на новой заявке.

AI восстановлен командой `docker compose start ai`. Финальный `docker compose ps`: все четыре сервиса healthy.

### Найденный дефект

Когда в структурированном вопросе чата был дан ответ `900000`, чат показал ответ, но первый план/подбор показывал собственные средства 0 ₽; из-за этого «Старт» оказался недоступен. После указания бюджета в профиле последующая естественная формулировка создала план с 900,000 ₽, а заданная фраза в резервном сценарии без AI тоже сработала правильно. Причина не установлена, исходники не менялись.

### Ошибки и ограничения

Ошибок API/контейнеров в завершённых сценариях не замечено. Ограничение артефактов: скриншоты отображались в ходе UI-проверки, но PNG-файлы не попали в каталог. Браузер отверг попытку перенести снятый экран через `data:` URL по политике безопасности; обходной способ не применялся. Подробности — `artifacts/ROUND4_windows/screenshot-capture-limit.txt`.
