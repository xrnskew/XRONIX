## 2. Что мы делаем

### 2.1 Продукт
Умный кабинет предпринимателя: человек описывает идею бизнеса → ИИ задаёт уточняющие вопросы → собирает персональный план (шаги, возможности, риски, цифры, потребность в финансировании) → кабинет показывает это красиво и подсказывает, какой кредит нужен и потянет ли его бизнес.

Важно: трек про **кредитный** кабинет, поэтому кредитная часть обязательна — без неё жюри не увидит попадание в кейс. План должен отвечать на вопрос «сколько денег нужно, откуда их взять и какой будет нагрузка».

### 2.2 Формат сдачи — сайт-презентация
- **Слева:** презентация проекта — проблема, решение, как работает, архитектура, команда.
- **Справа:** макет iPhone, внутри которого живой MVP-кабинет (работающий, не картинка).

### 2.3 Вкладки кабинета (MVP)
1. **Чат** — диалог с ИИ: идея → уточнения → готовый план.
2. **План** — дашборд по JSON от ИИ: шаги, цифры, графики, риски.
3. **Финансы / Кредит** — потребность в деньгах, подходящий кредит, калькулятор платежа, оценка нагрузки.
4. **Профиль** — данные предпринимателя и теги (их видит и учитывает ИИ), можно редактировать.

## 3. Пользовательский сценарий

```
1. Регистрация / вход
2. Короткий онбординг -> заполняется профиль (город, опыт, бюджет, сфера)
3. Чат: «Хочу открыть кофейню у метро»
4. ИИ задаёт 3–6 уточняющих вопросов (по одному или пачкой, с вариантами ответа)
5. Пользователь отвечает -> ИИ говорит «достаточно данных»
6. ИИ возвращает JSON-план -> бэк валидирует и сохраняет
7. Фронт рисует вкладку «План» + «Финансы/Кредит»
8. Бэк обновляет теги и сжатую память пользователя
9. При следующем диалоге ИИ уже знает контекст пользователя
```

## 4. Архитектура

```
[ Frontend (React) ]
        |  HTTPS, JWT
        v
[ Backend — Илья ]  ---- БД (пользователи, профиль, теги, память, чаты, планы)
        |  внутренний HTTP
        v
[ AI-сервис — Даня ]  ---->  GigaChat API
```

Ключевые принципы:
- **Фронт никогда не ходит в ИИ напрямую.** Только через бэк.
- **Токен GigaChat хранится только на сервере** (в `.env`, не в репозитории).
- **Бэк собирает контекст:** берёт профиль, теги, память и историю чата → отправляет в AI-сервис готовый пакет.
- **Бэк проверяет ответ ИИ по схеме.** Если JSON битый — повторный запрос (до 2 раз), потом понятная ошибка фронту.
- **AI-сервис ничего не хранит** — он «чистая функция»: получил контекст, вернул ответ.

### 4.1 Стек (предложение, финально решают владельцы частей)
- **Frontend:** React + Vite + TypeScript, Tailwind, react-router, Recharts (графики).
- **Backend:** FastAPI (Python) или Node (Express/Nest) — на выбор Ильи. БД: PostgreSQL (или SQLite, если так быстрее). Auth: JWT.
- **AI:** Python + официальная библиотека `gigachat`. Учесть: для API GigaChat нужен сертификат НУЦ Минцифры, иначе будут ошибки SSL — разобраться в первый день.
- **Запуск всего вместе:** `docker-compose` в корне (на этапе интеграции).

## 5. Контракты (самое важное)

Эти контракты фиксируем в первый день и дальше **все работают на моках**, не дожидаясь друг друга. Файлы схем лежат в `/contracts`.

### 5.1 Frontend <-> Backend

| Метод | Путь | Что делает |
|---|---|---|
| POST | `/api/auth/register` | `{email, password, name}` → `{token, user}` |
| POST | `/api/auth/login` | `{email, password}` → `{token, user}` |
| GET | `/api/me` | профиль + теги |
| PATCH | `/api/me` | обновить профиль/теги |
| GET | `/api/chats` | список диалогов |
| POST | `/api/chats` | создать диалог → `{chat_id}` |
| GET | `/api/chats/{id}` | история сообщений |
| POST | `/api/chats/{id}/messages` | `{text}` → ответ ИИ (формат ниже) |
| GET | `/api/plans/{id}` | сохранённый план |

Все ответы с ошибкой: `{ "error": { "code": "STRING", "message": "текст для пользователя" } }`

### 5.2 Ответ на сообщение в чате (это получает фронт)

ИИ отвечает одним из трёх типов:

```json
{ "type": "message", "text": "Обычный текстовый ответ" }
```

```json
{
  "type": "questions",
  "text": "Уточню пару моментов, чтобы план был точным",
  "questions": [
    { "id": "budget", "text": "Какой стартовый бюджет?", "kind": "choice",
      "options": ["до 500 тыс", "500 тыс – 2 млн", "больше 2 млн"] },
    { "id": "location", "text": "В каком городе?", "kind": "text" }
  ]
}
```

```json
{ "type": "plan", "text": "План готов", "plan_id": "uuid", "plan": { "...": "см. 5.3" } }
```

### 5.3 Схема плана (главное, что нужно от Дани)

```json
{
  "title": "Кофейня у метро",
  "summary": "Коротко суть в 2–3 предложениях",
  "business": { "sphere": "общепит", "format": "кофе с собой", "city": "Москва" },
  "steps": [
    { "order": 1, "title": "Регистрация ИП", "description": "...", "duration_days": 5, "cost_rub": 800 }
  ],
  "opportunities": [ { "title": "...", "description": "..." } ],
  "risks": [ { "title": "...", "level": "low|medium|high", "mitigation": "..." } ],
  "finance": {
    "startup_cost_rub": 1500000,
    "own_funds_rub": 500000,
    "funding_gap_rub": 1000000,
    "monthly_revenue_rub": 600000,
    "monthly_expenses_rub": 450000,
    "monthly_profit_rub": 150000,
    "payback_months": 10,
    "revenue_forecast": [ { "month": 1, "revenue_rub": 200000, "expenses_rub": 400000 } ]
  },
  "credit": {
    "needed": true,
    "amount_rub": 1000000,
    "purpose": "оборудование и аренда",
    "recommended_term_months": 24,
    "estimated_rate_percent": 22,
    "monthly_payment_rub": 51900,
    "debt_load_percent": 35,
    "verdict": "ok|risky|not_recommended",
    "comment": "Почему так"
  },
  "tags_update": ["общепит", "старт", "Москва", "бюджет до 2 млн"]
}
```

Правила для ИИ:
- Все суммы — **целые числа в рублях**, без пробелов и строк.
- Поля не пропускать: если данных нет — `null`, а не выдумка.
- Цифры ИИ — это оценка. **Финальные кредитные расчёты (платёж, нагрузка) пересчитывает бэк по формуле аннуитета**, чтобы цифры не «плыли».

### 5.4 Backend <-> AI-сервис

`POST /ai/respond`

Вход (собирает бэк):
```json
{
  "mode": "chat",
  "user_context": {
    "profile": { "name": "...", "city": "...", "experience": "...", "budget_rub": 500000 },
    "tags": ["общепит", "новичок"],
    "memory": "Сжатая выжимка того, что ИИ уже знает о пользователе"
  },
  "history": [ { "role": "user|assistant", "content": "..." } ],
  "message": "Последнее сообщение пользователя"
}
```

Выход: строго один из форматов из 5.2 (без `plan_id` — его ставит бэк).

`POST /ai/summarize` — обновить память
Вход: `{ "memory": "старая выжимка", "history": [...] }` → Выход: `{ "memory": "новая выжимка до ~800 символов", "tags": [...] }`

### 5.5 Память и теги
- **Теги** — короткие факты о пользователе (сфера, город, стадия, бюджет). Видны и редактируются во вкладке «Профиль».
- **Память** — короткий текст-выжимка. Обновляется бэком после завершения плана (или каждые N сообщений) через `/ai/summarize`.
- В каждый запрос к ИИ идут: профиль + теги + память + последние ~10 сообщений. Вся история целиком — не отправляется.

## 6. Репозиторий и работа с git

### 6.1 Структура (монорепо)
```
/frontend      — Александр
/backend       — Илья
/ai            — Даня
/contracts     — схемы API и JSON (меняются только через капитана)
/docs          — этот файл и прочие документы
docker-compose.yml
README.md
```

### 6.2 Ветки
| Ветка | Назначение | Кто пушит |
|---|---|---|
| `main` | Финальная рабочая версия для сдачи | только капитан, мерж из `dev` |
| `dev` | Интеграция — здесь всё собирается и запускается вместе | мержи из рабочих веток на контрольных точках |
| `frontend` | Работа Александра | Александр |
| `backend` | Работа Ильи | Илья |
| `ai` | Работа Дани | Даня |

### 6.3 Правила
1. Работаешь только в своей ветке и своей папке. Чужие папки не трогаешь.
2. Начало дня: подтянуть свежий `dev` в свою ветку.
   ```
   git checkout <своя-ветка>
   git pull
   git merge origin/dev
   ```
3. Коммиты маленькие и понятные: `feat: чат отправляет сообщения`, `fix: валидация плана`.
4. В `dev` — только через Pull Request, когда этап готов и у тебя всё запускается локально.
5. `.env` никогда не коммитим. В репо лежит `.env.example` с пустыми значениями.
6. Нужно поменять контракт — пишешь в чат команды, правим `/contracts` вместе, потом все подстраиваются.
7. На контрольной точке: все мержат в `dev` → капитан запускает всё вместе → чиним → идём дальше.
