Даня, начинай раунд 1. Ветка `backend-ai` уже создана на GitHub от `backend` после слияния с `dev`, коммит `b7d26eb`.

Цель: подготовить модельную часть — лицензии, генераторы проверенных датасетов и базовую оценку.
Главный метод — `/ai/consult`; `/ai/parse-need` второй.

Перед работой:

```bash
git fetch origin
git checkout backend-ai
git pull --ff-only origin backend-ai
```

Прочитай `docs/tasks/ROUND1.md`, `docs/tasks/ROUND1_ADDENDUM.md`, `contracts/ai.md`,
схемы `contracts/schemas/consult.schema.json`, `parse-need.schema.json`, примеры `consult.*.json`.

Конкретные действия:

1. Сначала `ai/LICENSES.md`: по первоисточникам проверь, разрешено ли обучение другой модели
   на ответах GigaChat API, есть ли открытые веса GigaChat 3 и какая лицензия. Выбери открытую
   базовую модель до ~2 млрд параметров. Укажи ссылки и ограничения. До проверки условий
   не генерируй датасет через GigaChat; при запрете используй допустимую открытую модель.
2. Сделай генератор `/ai/consult`: сначала выбирай ожидаемый `state`, затем генерируй под него
   реплики и ожидаемый тип ответа `questions`, `message`, `ready`. Покрой сферы, города,
   свои деньги и ответы анкеты. До 4 уточняющих вопросов за раз. Для запросов не про бизнес
   и попыток сменить роль — `message`, состояние без изменений. Модель не считает план,
   не придумывает суммы и не обещает кредит.
3. Подготовь отдельный датасет `/ai/parse-need`: все цели и сферы из `dictionaries.json`, города
   из `frontend/src/data/cities.json` (только чтение), суммы цифрами/словами, сроки словами,
   опечатки, пропуски суммы/города, неоднозначные фразы, запросы не про бизнес.
4. Проверяй каждый пример соответствующей JSON Schema. Ориентир ROUND1 — 2–3 тыс.
   обучающих примеров и 200+ в отдельной holdout. Раздели заготовки до генерации вариантов,
   чтобы варианты одной заготовки не попадали одновременно в train и holdout.
   Отдельно укажи размеры обоих датасетов. Добавь примеры по каждому правилу `/ai/consult`.
5. `ai/dataset/evaluate.py`: точность каждого поля state и типа ответа для consult,
   доля придуманных сумм, которых не было у человека (должна быть 0), точность каждого
   поля для parse-need. Прогони простое базовое решение, сохрани результаты.
   Генерация, валидация и оценка должны воспроизводиться по командам из README.

Согласованные зависимости: API и схемы не меняем. Числа плана считает бэкенд по шаблонам,
кредитное решение — правила бэкенда. Интеграцию `/ai/consult` с новым чатом делает Илья
во втором раунде; твоя часть сейчас — данные, лицензии и оценка. При неудобном контракте
сообщи Илье до обходных решений.

Ожидаемый результат: файлы в `ai/`, записка о лицензиях, генераторы, проверенные датасеты,
отдельные holdout, скрипты оценки и сохранённый вывод базового прогона.

Критерии готовности: команды воспроизводятся, каждый пример проходит схему, holdout не
используется при обучении, покрыто каждое правило `/ai/consult`, есть метрики и описаны ограничения.
Если весь объём ещё не готов, сначала пришли записку о лицензиях и первый проверенный набор
consult с примерами по каждому правилу, затем продолжай полный объём.

Коммить и пушь только в `backend-ai`. Фронтенд, контракты и `backend` не меняй;
в `dev` не сливай, старую `ai` не удаляй. Илья принимает результат и объединяет в `backend`.
