# XRONIX Backend · контракты v1

Рабочий MVP на FastAPI, Python 3.12+, SQLAlchemy и SQLite. Все пути и JSON соответствуют `contracts/api.md` и `contracts/ai.md`. Исходные контракты загружаются из соседней папки `contracts`, без копирования схем в код.

## Запуск одной командой

Из корня репозитория (нужны Python 3.12+ и доступ к PyPI при первом запуске):

```sh
./backend/run.sh
```

Скрипт создаёт `backend/.venv`, устанавливает зависимости, запускает Uvicorn на **0.0.0.0:8000**. База создаётся автоматически. По умолчанию включён `MOCK_AI=true`: сервис Дани не нужен.

Если системный Python старше 3.12, укажите нужный исполняемый файл при первом запуске: `PYTHON=python3.13 ./backend/run.sh`.

- API: http://localhost:8000/api
- Проверка: http://localhost:8000/health → `{"status":"ok"}`
- Swagger: http://localhost:8000/docs

## Переменные окружения

Необязательно скопировать `backend/.env.example` в `backend/.env` и отредактировать. Переменные процесса имеют приоритет над `.env`.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `MOCK_AI` | `true` | `false` включает HTTP-запросы к настоящему ИИ |
| `AI_SERVICE_URL` | `http://localhost:8001` | Базовый URL AI-сервиса, без `/ai` |
| `CORS_ORIGINS` | `http://localhost:5173,http://127.0.0.1:5173` | Разрешённые origin через запятую, без завершающего `/` |
| `JWT_SECRET` | пусто | Для развёртывания задайте случайный секрет от 32 байт |
| `JWT_EXPIRE_MINUTES` | `1440` | Срок действия токена |
| `DATABASE_URL` | абсолютный путь к `backend/data/xronix.db` | SQLite URL, например `sqlite:////srv/backend/data/xronix.db` |
| `CONTRACTS_DIR` | соседняя `contracts/` | Папка с контрактами v1 |

Без `JWT_SECRET` создаётся случайный приватный файл `backend/data/jwt.key` (права 0600). Он сохраняется между перезапусками, поэтому действующие JWT продолжают работать. `backend/data/`, `.env` и виртуальные окружения исключены из Git. Сохраняйте весь каталог `data/`, включая ключ; для резервной копии работающей SQLite используйте SQLite backup API, учитывая WAL.

Для настоящего ИИ:

```sh
MOCK_AI=false AI_SERVICE_URL=http://localhost:8001 ./backend/run.sh
```

Секрет GigaChat здесь не нужен: он остаётся в AI-сервисе.

## Саше: подключение frontend

Существующий frontend-клиент из `origin/frontend` уже поддерживает этот API. В его локальном `.env`:

```dotenv
VITE_USE_MOCKS=false
VITE_API_URL=http://localhost:8000
```

Перезапустить Vite. `VITE_API_URL` **без `/api`** — клиент добавляет префикс самостоятельно. Создать аккаунт в интерфейсе: клиент сохранит JWT и добавит `Authorization: Bearer <token>`.

Сценарий проверки:

1. Зарегистрироваться, при желании заполнить профиль.
2. Создать чат, отправить «Хочу открыть кофейню у метро».
3. Backend вернёт три вопроса из `contracts/examples/reply.questions.json`.
4. Отправить ответы связным `text` и необязательным массивом `answers`.
5. Backend вернёт `type=plan`, свой `plan_id` и сохранённый план. Платёж в примере: 51 878 ₽, нагрузка 35%, вердикт `ok`.
6. Перезагрузить страницу: `GET /api/plans` и `GET /api/plans/{id}` восстановят план. История доступна через `GET /api/chats/{id}`.

Моковые данные демонстрационные, из контрактных примеров: они не подстраиваются под бизнес пользователя. Каждый чат независимо проходит вопросы → план; следующие сообщения получают обычную реплику. Прогресс хранится в БД. Новый сценарий начинается в новом чате.

Если frontend открывают на другом компьютере, вместо `localhost` нужен доступный адрес backend; origin frontend нужно добавить в `CORS_ORIGINS`.

## Поведение backend

- Пароли: PBKDF2-HMAC-SHA256, 600 000 итераций, индивидуальная случайная соль; сравнение постоянного времени. JWT: HS256, проверка подписи, срока, issuer и audience.
- Чужие чаты и планы всегда дают `NOT_FOUND`, списки фильтруются по пользователю.
- В ИИ передаются профиль, теги, память, последние 10 сообщений **без текущего**, текущее сообщение только как `text` → `message`. `answers` сохраняется локально и в ИИ не отправляется. Ответы ассистента в контексте включают вопросы/план.
- Все ответы ИИ проверяются исходными JSON Schema draft-07 и смысловыми правилами `check.mjs`. При невалидном результате: первоначальная попытка и до двух повторов. Весь `/ai/respond`, включая повторы, ограничен 30 секундами. Сетевые ошибки/таймауты дают `AI_UNAVAILABLE`, исчерпанные невалидные ответы — `AI_BAD_RESPONSE`.
- Финансовые противоречия, неправильные месяцы/порядок шагов, неполный кредит и слишком маленькая сумма кредита отклоняются до сохранения. После проверки сервер сам пересчитывает funding gap, прибыль, аннуитет, нагрузку и вердикт; проверяет результат снова. Пороги: ≤35% `ok`, ≤50% `risky`, >50% `not_recommended`; прибыль ≤0 означает нагрузку 100%. `recommended_product_id=null` до подключения подбора.
- Сообщение пользователя сохраняется даже при сбое ИИ. Невалидный ответ и план не сохраняются. Повторная отправка создаёт новое сообщение; автоматической идемпотентности контракт v1 не задаёт.
- Одновременная отправка в один чат даёт `RATE_LIMITED` (429, `Retry-After: 2`). Блокировка через SQLite работает между процессами; при аварии снимается по истечении 120 секунд.
- После готового плана `/ai/summarize` обновляет память и добавляет теги без дублей, максимум 12. Это фоновая задача: ответ с планом не ждёт её, сбой не отменяет план и сохраняет прежнюю память. Не является долговечной очередью: при аварийной остановке до завершения сводка может не обновиться.
- Все ошибки API имеют `{ "error": { "code": "…", "message": "…" } }`, сообщения по-русски без технических деталей. Ошибки валидации — 400, а не стандартные FastAPI 422.

## Проверки

```sh
cd backend
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python -m pytest -q
.venv/bin/python tests/smoke.py
```

Последняя команда требует свободный порт 8000. Она запускает настоящий Uvicorn, выполняет HTTP-сценарий и перезапускает процесс с той же временной SQLite, проверяя JWT, планы, сообщения и моковое состояние. Тестовые данные автоматически удаляются.

Контракты проверяются отдельно из корня:

```sh
cd contracts && npm ci && npm run check
```

## Docker

Сборка **из корня репозитория**, чтобы были доступны оригинальные контракты:

```sh
docker build -f backend/Dockerfile -t xronix-backend .
docker run --rm -p 8000:8000 -e MOCK_AI=true -v xronix-data:/srv/backend/data xronix-backend
```

Для реального AI добавьте `-e MOCK_AI=false -e AI_SERVICE_URL=http://ai:8001` и общую Docker-сеть. Для настройки секретов используйте окружение или `--env-file backend/.env`. Именованный том хранит SQLite и локальный JWT-ключ между контейнерами. Контейнер работает под непривилегированным пользователем.

## Готовность и ограничения

Готовы auth/JWT, профиль, изолированные чаты, сохранение сообщений и планов, моковый диалог, HTTP-интеграция ИИ с валидацией/ретраями/таймаутом, память/теги, финансовые расчёты, CORS, health, автосоздание БД, Dockerfile, тесты.

Результаты фактических проверок записаны в `TEST_RESULTS.md`. Настоящий сервис Дани нужно проверить совместным запуском; тесты HTTP-интеграции используют управляемый `httpx.MockTransport`. Подбор продукта пока возвращает разрешённый `null`. Развёртывание и merge в dev/main выполняются командой отдельно.
