# QA fixes — 19 October 2026

- Launch cost now covers the sum of known step costs. Gap, loan amount, payment, load and payback are recomputed together. GET chat/plan views also repair derived figures from legacy records without overwriting historical JSON.
- An explicit refusal of credit is enforced outside the model, including structured answers bound to server question IDs. The funding gap stays visible with alternatives to borrowing.
- Unsupported assumptions about a metro location produce a clarification. Invalid metro claims in generated plans are rejected and retried with feedback. This conservative guard is not a general geographic fact-checker.
- Browser sessions opt in with `X-Session-Mode: cookie`. Login/register set a host-only HttpOnly SameSite=Strict cookie (Secure and __Host prefix on HTTPS). Existing bearer API clients keep their response format and continue to work.
- Cookie writes require an allow-listed Origin. CORS allows credentials only for the configured exact origins.
- POST /api/auth/logout clears the cookie and revokes its token. Revocations use namespaced, hashed keys in the existing expiring rate_buckets table; no DB migration is needed. Token IDs make repeated logins distinct. API responses are no-store.
- Deploy backend before the matching frontend. Existing browser users must sign in once after the frontend removes the legacy localStorage token. Use the custom xronix.ru domain; Strict cookies do not support a third-party github.io → API browser session.

Validation: full backend suite (137 passing tests), including authentication/isolation, CSRF/cookie/logout, budget repair and credit refusal. Additional structured-answer assertion ran in the regression suite. Frontend validation is documented in frontend/QA_FIXES_2026-10-19.md on the frontend branch.

Scope: general LLM truthfulness, production load tests and external penetration testing remain separate work. Frontend HTTP framing/security headers require a capable hosting layer; GitHub Pages cannot set arbitrary response headers.
