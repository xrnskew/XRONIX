## Запуск

Из корня репозитория запустить отдельный мок по `integrations-mock/README.md`, затем:

```bash
cd backend
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt -r requirements-dev.txt
INTEGRATIONS_URL=http://127.0.0.1:8002 .venv/bin/uvicorn app.main:create_app --factory --host 127.0.0.1 --port 8000
```

Работать на тестовой базе. Чтобы явно выбрать новую базу, задать `DATABASE_URL=sqlite:////tmp/xronix-round1.sqlite`.
Миграция 4 применяется при запуске. Для существующей базы сохраняется прежний механизм проверенного
снимка перед миграцией; при нескольких процессах остановить их до обновления схемы.

API: `http://127.0.0.1:8000/docs`. Зарегистрировать клиента через `/api/auth/register`.
Для curl использовать полученный `token` в `Authorization: Bearer <token>`.
Для cookie-режима передавать разрешённый `Origin`, как в существующем API.

В `/docs` нажать **Authorize** и вставить `token` из регистрации/входа (без префикса `Bearer`).
Все защищённые методы содержат схему HTTP Bearer в OpenAPI.

## Основной сценарий

1. `POST /api/companies`: `{"inn":"7715881399","member_role":"owner"}`.
2. `POST /api/applications`, подставив полученный ID компании:

```json
{
  "company_id": "<id>",
  "product_id": "fast",
  "purpose": "equipment",
  "amount_rub": 1500000,
  "term_months": 24,
  "financials": {
    "revenue_12m_rub": 24000000,
    "expenses_12m_rub": 19200000,
    "loan_payments_monthly_rub": 40000
  },
  "consent_bki": true
}
```

3. `POST /api/applications/{id}/submit`: `{"version":1}`.
4. `GET /api/applications/{id}` раз в 2 секунды. Ожидается:
   `draft → submitted → checking → scoring → approved`, платёж **78 933 ₽**, ставка 23,5%.
5. `accept`, затем `sign` — с актуальной `version` из предыдущего ответа. Итог `funded`.
6. Устаревшая версия → `409 VERSION_CONFLICT`; запрещённое действие → `409 INVALID_TRANSITION`;
   незаполненные поля → `422 INCOMPLETE_APPLICATION`, перечень также виден в `missing_fields` черновика.

Паузы автоматических этапов берутся из `rules.checks.stage_delay_seconds` (используется нижняя граница).
Очередь хранится в SQLite: перезапуск не теряет заявку. Захват задания атомарный, аренда 30 с;
после аварии повторный обработчик дождётся окончания аренды. События, решение и статус записываются
одной транзакцией; версия защищает от конкурирующих изменений.

## Остальные компании

Полные тела заявок: `app/catalog/demo_applications.json`. Эти значения повторяют эталон фронта.

| ИНН | Сумма / срок | Продукт | Исход |
|---|---|---|---|
| 7715881399 | 1 500 000 / 24 | fast | approved |
| 777309114120 | 2 000 000 / 24 | fast | counter_offer, срок 60 |
| 7768151886 | 12 000 000 / 60 | secured | manual_review |
| 7755761690 | 1 000 000 / 24 | fast | declined, overdue_90 |
| 776846978815 | 600 000 / 24 | fast | declined, business_too_young на 20.10.2026 |
| 7772731777 | 900 000 / 24 | fast | info_requested при member_role=accountant |

Для последнего сценария загрузить доверенность через `/api/companies/{id}/authority`
либо документ `kind=authority_document` через `/api/applications/{id}/documents`, затем повторить `submit`.
Файлы до 5 МиБ хранятся под случайными именами в `uploads/` рядом с базой, с правами 0600.
Исходное имя очищается от пути; содержимое сервер не исполняет. При переносе базы сохранять также `uploads/`.

При `FAIL_INN` после привязки компании новая заявка достигает `manual_review`,
результаты недоступных проверок сохраняются как `error`. Таймаут каждого запроса к моку — 5 с.

## Будущий ИП и «Старт»

1. Создать компанию с `{"inn":"772519083310","member_role":"owner","future":true}`.
2. `POST /api/plans/calculate`:
   `{"sphere":"coffee","city":"Казань","own_funds_rub":500000,"answers":{}}`.
3. `/api/products/match`: передать IDs компании и плана, сумму из `plan.finance.funding_gap_rub`,
   срок 36, цель `new_location`, `has_collateral:true`. Ответ содержит пять продуктов;
   `start` помечен `demo:true`, продукты Альфы для `person` недоступны.
4. Создать заявку `product_id=start`, `plan_id` из расчёта, срок 36,
   залог `{"kind":"guarantor","description":"Поручитель","value_rub":1000000}`,
   финансы `{"revenue_12m_rub":null,"expenses_12m_rub":null,"loan_payments_monthly_rub":0}`,
   `consent_bki:true`. Сумму можно не передавать — берётся дефицит средств плана.
5. Подать. Ожидается одобрение с условием регистрации ИП последней строкой `offer.explanation`.
   ЕГРЮЛ и ФНС для `person` не вызываются, БКИ вызывается по личному ИНН.
6. План с долей своих меньше 20% показывает причину на подборе и даёт отказ `own_funds_low`
   в конвейере. Без плана — `plan_required`; поручитель/залог обязателен для подачи.

Шаблоны и правила читаются из `contracts/`. Снимок параметров банковских продуктов и список городов
лежат в `app/catalog/`, скопированы из эталона фронта на `b7d26eb` для автономной сборки Docker.
Это синтетический расчёт по согласованным снимкам, не актуальная банковская оферта.
