# THIRD_PARTY_NOTICES

> Черновик к сдаче (раунд 2). Раздел «Модель и датасет» дополнит Даня после дообучения. Перед заморозкой сверить версии с lock-файлами и `requirements*.txt`.

Сторонние компоненты, модели, данные и сервисы, которые использует XRONIX, и смоделированные интеграции. Для каждого пакета указана лицензия из его метаданных. Полные тексты лицензий распространяются вместе с пакетами (`node_modules/*/LICENSE`, `site-packages/*.dist-info`). Всё, что не перечислено, написано командой XRONIX.

Проверяемая версия **не зависит от платных подписок, платных API и закрытых лицензий** (кейс, с. 10). Все внешние системы банка и государства заменены локальными моками на синтетических данных.

## 6. Смоделированные интеграции

Настоящие системы не вызываются. Сервис `integrations-mock` повторяет смысл интеграции по HTTP-контракту [`contracts/integrations.md`](contracts/integrations.md) и подписывает каждый ответ полем `source`.

| Что моделируем | Настоящая система | Метод мока | Что возвращает |
|---|---|---|---|
| Регистрационные данные компании | ЕГРЮЛ / ЕГРИП (ФНС России) | `GET /egrul/{inn}` | статус, дата регистрации, ОКВЭД, адрес, руководитель |
| Проверка контрагента | сервис ФНС «Прозрачный бизнес» | `GET /fns/{inn}` | массовый адрес, недоимка, дисквалификация руководителя |
| Кредитная история | бюро кредитных историй | `POST /bki/report` | открытые кредиты, платежи, просрочки 30+ и 90+, длина истории |
| Электронная подпись договора | УКЭП / ПЭП банка | внутри бэкенда | подтверждение кнопкой в кабинете, без юридической силы |
| Выдача кредита | АБС банка | внутри бэкенда | статус «Выдано» и график платежей, без перевода денег |

Для шести именных ИНН (сценарии в README) мок отдаёт заранее известный результат, для любого другого корректного ИНН — детерминированные данные из хеша ИНН.
