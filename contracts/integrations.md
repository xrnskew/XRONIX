# Backend ↔ integrations-mock

Отдельный сервис, который изображает внешние системы: ЕГРЮЛ/ЕГРИП, «Прозрачный бизнес» ФНС и бюро кредитных историй. Бэкенд ходит в него так же, как ходил бы в настоящие системы. Схемы: [`integrations.schema.json`](schemas/integrations.schema.json).

Адрес: `INTEGRATIONS_URL`, по умолчанию `http://localhost:8002`. Внутренняя сеть, без авторизации. Таймаут на стороне бэкенда 5 с.

## Данные
- Компании для сценариев демо лежат в `integrations-mock/data/companies.json` и всегда дают одинаковый результат (таблица ниже).
- Любой другой ИНН с верной контрольной суммой тоже находится: данные генерируются детерминированно из SHA-256 ИНН. Один ИНН — всегда одна и та же компания. Большинство таких компаний «хорошие», примерно каждая пятая с проблемой.
- Неверная контрольная сумма: `400 { "error": { "code": "INVALID_INN", … } }`.
- Все данные синтетические. Совпадение с реальной компанией случайно.

## `GET /egrul/{inn}` → `integrations#/egrul`
## `GET /fns/{inn}` → `integrations#/fns`
## `POST /bki/report` → `integrations#/bki_report`
Тело `integrations#/bki_request`. Без `consent: true` — 400 `VALIDATION_ERROR`.
## `GET /health` → `{ "status": "ok" }`

Для проверки отказоустойчивости: если у сервиса задана переменная `FAIL_INN`, на этот ИНН все методы отвечают 503.
